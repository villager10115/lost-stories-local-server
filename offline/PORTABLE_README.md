# Lost Stories 本地离线客户端

双击本目录 `LostStories.exe`，选择“启动游戏”。无需 DMM，不读取 DMM 登录参数。
第一次启动会检查文件、备份存档、启动两个本地服务并按已记录的资源请求树预检，再打开游戏。
游戏退出后服务随之关闭；请正常退出游戏后再关闭启动窗口。

## 换电脑

1. 正常退出游戏和启动器。
2. 复制整个 `LostStories_Offline` 文件夹到另一台 Windows x64 电脑的可写目录。
3. 双击 `LostStories.exe`，先点“校验完整文件”，通过后启动。

不要只复制 EXE。Unity、资源、Python 运行库和服务端均随文件夹携带。
路径可包含中文和空格；不要求相同盘符，也不需要预装 Python 或开发工具。
目标机器仍需具备运行此 Unity 游戏所需的 Windows、图形驱动及系统组件。
未在第二台实体电脑实机验收，不能据此保证所有硬件均可运行。

## 存档与备份

- `data/state/state.sqlite`：本地账号与玩法状态。
- `data/page/`：页面和编队存档。
- `data/native/`：本包原生客户端数据与 WebView 缓存，不依赖原电脑的 AppData 缓存。
- `snapshots/`：启动前自动备份。
- `logs/`：启动与服务错误日志。

本包是用户自己的存档迁移包，包含现有本地进度；不要直接作为公开分发包。
原独立包与正式存档保留在原位置。开始使用新包后，两个包的存档不自动同步。
显示/音量等 Unity PlayerPrefs 设置可能随机器重置，不影响服务端角色存档。

## 当前范围

完整覆盖清单见 `reports/FLOW_COVERAGE.md`。已有页面、抽卡、编队、部分强化、任务领取等功能沿用现有实现。
战斗等核心玩法仍有未实现链路；封装成功不代表完整复现官服。
端口 18865、18866、9333 被占用时启动器会明确停止，不复用其他程序的服务。
不需要 Windows Sandbox，不修改全局 hosts、代理或 DMM 配置。

## 故障检查

先点“校验完整文件”。文件缺失时从保留副本恢复，不要用旧版同名资源替代。
启动失败查看窗口消息和 `logs/state.log`、`logs/page.log`、`logs/Player.log`。
迁移后校验通过仅证明文件完整；实际画面、登录与玩法还需在目标机器检查。
